# GLM-5.2 SQG W4A8 on Infernal Invocation r13

**Status: qualified for TP4/DCP1/MTP0 on four 96 GB SM120 GPUs.** The
published profile serves `brandonmusic/GLM-5.2-SQG-W4A8` through native B12X
SQG kernels. DCP, MTP, higher concurrency, and other tensor-parallel
geometries are unsupported by this qualification.

## Checkpoint Format

SQG is the scalar quantization codebook used to reconstruct compact weights.
The checkpoint's bitrate assignment and tensor selection are separate from
the codebook itself. This checkpoint uses Luke Alonso's SQG coding primitive
with Brandon Music's GLM-5.2-specific tensor profile:

| Tensor class | Stored form |
|---|---|
| Routed expert matrices | 384 K3 and 384 K4 matrices per routed layer, independently assigned per tensor |
| Non-routed eligible matrices | 380 K6 matrices |
| Tensors outside the SQG profile | BF16 |
| Codebook | `sqg_xor_cheb_t12` |
| Schema | `glm52_sqg_atoms_v2` |
| Physical permutation | Disabled |
| Indexed tensor storage | 343,012,670,960 bytes |
| Effective indexed-weight density | Approximately 3.64 bits per original parameter |

This is not a canonical QSRT checkpoint copied unchanged. It reuses the SQG
representation while selecting K3, K4, K6, or BF16 according to the GLM-5.2
profile. The mixed assignment preserves sensitive tensors and spends more
bits where the profile predicts a quality benefit. A different assignment
requires a different checkpoint; the runtime does not infer or change those
K3/K4 decisions at load time.

## Runtime Contract

B12X reads the serialized SQG atoms directly. Routed expert kernels decode K3
and K4 atoms to E4M3 values inside the W4A8 compute path. The native K6 linear
kernel decodes non-routed matrices without retaining a reconstructed BF16
copy. The EXL3 quantization name is the vLLM loader interface for this schema;
the weight execution path is B12X SQG, not the ExLlama GEMM backend.

All four ranks must emit a complete
`glm52-native-sqg-w4a8-rank-evidence-v1` record. A valid record lists routed
layers 3 through 77 as both loaded and executed, names `full-w4a8` as the
activation endpoint, and sets `allow_a16_fallback` to `false`.

## Start the Server

Download the immutable Compose specification and start it:

```bash
curl -LO https://raw.githubusercontent.com/local-inference-lab/blackwell-llm-docker/575416191/examples/docker-compose-glm52-sqg-infernal-invocation-r13.yml
docker compose -f docker-compose-glm52-sqg-infernal-invocation-r13.yml up -d
```

The qualified configuration is intentionally fixed:

| Setting | Value |
|---|---|
| Tensor/decode context parallelism | TP4 / DCP1 |
| Speculative decoding | Disabled (`MTP=0`) |
| Scheduler | `MAX_NUM_SEQS=1`, `MAX_NUM_BATCHED_TOKENS=2048` |
| CUDA graph cap | 6 rows |
| Context limit | 32,768 tokens |
| GPU memory utilization | 0.96 |
| Routed experts | Native B12X SQG W4A8 |
| Non-routed SQG | Native B12X K6 |
| Attention | B12X sparse MLA |
| KV cache | NVFP4 DS-MLA |
| All-reduce | pynccl; custom all-reduce disabled |
| Loading | InstantTensor `BUFFERED`, `INSTANTTENSOR_COPY=0` |
| Decode graphs | FULL and PIECEWISE rows 1 through 6 |

Set deployment paths without changing the qualified execution geometry:

```bash
GPUS=4,5,6,7 PORT=5800 \
HF_CACHE=/srv/huggingface \
JIT_CACHE=/srv/cache/glm52-sqg-infernal-r13 \
docker compose -f docker-compose-glm52-sqg-infernal-invocation-r13.yml up -d
```

The JIT directory is keyed to the image, checkpoint revision, and serving
profile. Reusing a cache generated by a different image or quantization schema
is unsupported.

## Quantization Quality

Lower mean KLD is better. All rows use the same evaluation harness and
checkpoint prompt corpus.

| Weight and KV configuration | Mean KLD |
|---|---:|
| SQG weights, BF16-equivalent dense KV diagnostic | 0.078648 |
| SQG weights, FP8 KV | 0.081009 |
| SQG weights, NVFP4 KV | 0.123746 |
| EXL3 R7 with runtime K6, FP8 KV reference | 0.077949 |
| EXL3 R7 with runtime K6, NVFP4 KV reference | 0.108828 |

The BF16-equivalent value uses `index_topk=0` with `TRITON_MLA`; it is a
dense-attention diagnostic rather than the production sparse-attention
profile. Against the EXL3 R7 reference, SQG increases mean KLD by approximately
3.9% with FP8 KV and 13.7% with NVFP4 KV. KLD detects distribution drift but
does not replace task-level or long-context quality evaluation.

## Qualification Boundary

- **Qualified:** pinned checkpoint revision, TP4/DCP1/MTP0,
  `MAX_NUM_SEQS=1`, graph rows through 6, NVFP4 DS-MLA KV, native global SQG
  rank table, startup, FULL graph capture, CC1 decode, and 8K uncached prefill.
- **Implemented:** direct K3/K4 routed W4A8 execution, native non-routed K6
  execution, strict rank evidence, and InstantTensor borrowed-buffer loading.
- **Unsupported:** DCP greater than one, MTP, TP6, TP8, higher concurrency,
  alternate SQG schemas, and the shared SQG rank-table branch.

Test reports must include the image digest, checkpoint revision, TP/DCP/MTP,
physical GPU order, PCIe topology, context length, concurrency, graph cap, KV
dtype, and all four rank-evidence files.
