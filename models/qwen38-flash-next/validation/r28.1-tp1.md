# Qwen TP1/MTP3 qualification for the Jovian Judgement R28.1 image

Status: **qualified** for the bounded text-serving, GPU-prefix-cache,
performance and exact-repetition checks below. Broader model quality is
**research-only**. TP2, LMCache, vision and overclocked performance are not
qualified by these measurements.

The [deployment page](../../qwen38-flash-next.md) supplies a portable Compose
recipe. Its default model name resolves Hugging Face `main`; the exact
checkpoint revision used for this evidence is recorded here, not imposed on
public launch commands.

Status of the portable recipe: **implemented**. Docker Compose rendering and
CPU-only shell argument capture verify TP1/TP2 GPU selection, host/device PLE
selection, an unset `NCCL_GRAPH_FILE` and explicit draft-head A16. Each probe
matches all serving arguments after the intended model-path, port and TP
substitutions, plus 62 non-cache-directory runtime settings from the qualified
TP1 container. No GPU inference or model download was performed by these
recipe probes; they do not constitute TP2 or device-resident PLE qualification.

## Cache and bounded output checks

Cold/restored JSON copying passed at concurrency 1/2/3/4/8/16. Shared
SYSTEM/developer instructions with different user continuations restored
2,080 tokens; salted controls restored zero. Post-prefill logprobs checks
passed at concurrency 3/16. All three timed boots had zero preemptions, engine
errors, unfilled concurrency or confirmed exact loops. These are GPU-local
prefix checks, not LMCache RAM/disk or restart-restore tests.

Both images completed twelve long-output captures: eight encyclopedia
requests, two exact prime-number JSON requests and two LRU coding requests.
Temperature/top-p/top-k were unchanged, with explicit xhigh reasoning and a
32,768-output-token cap. Four encyclopedia requests suppressed EOS as a
repetition stress test. Reference output totaled 314,020 tokens; community
output totaled 306,598. Both had zero confirmed exact loops, zero client safety
stops and matching usage/server token accounting. All eight encyclopedia
requests reached the token cap; the four JSON/code requests ended normally.

These correctness captures ran on two separate stock GPUs to reduce elapsed
validation time. Their wall times are not an image throughput comparison.
The corpus detector script SHA-256 is
`4a21861a59b1cd711138f901393e0788b681b2b547e223de7884ea541c32762e`,
distinct from the headline decode client. Exact-loop checks do not exclude
semantic repetition or establish encyclopedia factual accuracy.

### Generated-code limitations

Both community-image LRU responses contain test-code defects:

- Seed `2026090601` calls `wasSuccessful()` on the `TestProgram` returned by
  `unittest.main()`, instead of on `program.result`, causing `AttributeError`.
- Seed `2026090602` uses `assertNotIn([1, 2], cache)` with dictionary-backed
  membership, raising an uncaught `TypeError` for the unhashable list.

Minimal standard-library reproductions confirm both failures. Python syntax
checks passed, but the complete generated programs were not executed. These
two stochastic outputs do not identify a backend or quantization cause.

## Draft-head activation diagnostic

Status: **research-only; not qualified for concurrent speculative performance**.
The image's inherited `VLLM_LM_HEAD_A16=0` gives a private W4A4 draft head.
Three diagnostic C8/C16 repeats showed near-zero draft acceptance and median
output of approximately 363/524 tok/s. Using `VLLM_LM_HEAD_A16=1` with the same
image/source/CLI and a separate compiler-cache namespace restored 29–34%
draft acceptance in all six C8/C16 windows. The BF16 target head was unchanged.
Short correctness checks passing under W4A4 did not establish useful MTP
execution. No kernel-level root cause is claimed. Diagnostic results are
separate from the precision-matched reference/community comparison.
